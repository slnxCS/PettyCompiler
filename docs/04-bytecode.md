# 04 — Формат байткода PTVM (версия 1.392)

Компилятор генерирует один бинарный файл (путь задаётся опцией `-o`) для стековой виртуальной машины PTVM.
Этот раздел — контракт между компилятором и VM.

> Семантика инструкций (что снимается со стека и что кладётся на него) выведена из того, какой код
> генерирует компилятор, и сверена с реализацией VM (`~/PettyLang/Interpreter`). При расхождениях приоритет у VM.

## 1. Соглашения

| Обозначение | Размер | Кодирование |
|---|---|---|
| `u8` | 1 байт | беззнаковое |
| `i32` | 4 байта | знаковое целое, little-endian |
| `f32` | 4 байта | IEEE 754 single, little-endian |
| `str(n)` | n байт | UTF-8 без завершающего нуля; длина `n` хранится отдельным `i32` перед строкой |
| `op` | 1 байт | код инструкции (`OpCode : byte`) |

Все многобайтовые значения пишутся через `BitConverter`, т. е. в порядке байт платформы
(на всех поддерживаемых .NET-платформах — little-endian).

## 2. Структура файла

```
┌──────────────────────────── HEADER ─────────────────────────────┐
│ magic          6 байт   ASCII "[PTVM]"                          │
│ version        f32      1.392                                   │
│ constCount     i32                                              │
│ constants[constCount]   см. §3                                  │
├──────────────────────────── FUNCTIONS ──────────────────────────┤
│ funcCount      i32                                              │
│ functions[funcCount]    тела функций верхнего уровня, см. §4    │
├──────────────────────────── CLASSES ────────────────────────────┤
│ classCount     i32                                              │
│ classes[classCount]     см. §5                                  │
├──────────────────────────── GLOBALS ────────────────────────────┤
│ globalCount    i32                                              │
│ <код инициализации глобальных переменных>                       │
│ HALT                                                            │
├──────────────────────────── ENTRY ──────────────────────────────┤
│ CALL <Main.ID> 0                                                │
│ HALT                                                            │
└─────────────────────────────────────────────────────────────────┘
```

Каждая функция и каждый метод начинаются с поля длины (§4), поэтому загрузчик может пропускать их
целиком, не декодируя инструкции. Секции глобалов и точки входа длины не имеют и заканчиваются `HALT`.

**Адреса переходов** (`JMP_IF_FALSE`) — абсолютные смещения от начала файла, включая заголовок.

## 3. Пул констант

Каждая запись: `u8 type`, затем значение.

| `type` | Константа | Значение |
|---|---|---|
| `0` | `CONSTANT_INT` | `i32` |
| `1` | `CONSTANT_FLOAT` | `f32` |
| `2` | `CONSTANT_BOOL` | `u8` (`0`/`1`) |

Константы дедуплицируются по значению (C#-`record`-равенство): одинаковые литералы получают один индекс.
Индексы назначаются в порядке первого появления литерала при семантическом анализе. Инструкция
`PUSH_CONSTANT idx` ссылается на запись с номером `idx` (с 0).

## 4. Функции

Секция функций содержит `funcCount` записей, каждая имеет вид:

```
length          i32        ; длина тела в байтах, НЕ включая само поле length
RESERVE_LOCALS  n:i32      ; n = число локальных слотов, включая параметры
<код тела>
RET                        ; добавляется всегда
```

Следующая функция начинается сразу после последнего байта тела, то есть через `4 + length` байт от начала
записи. Точка входа функции (куда передаёт управление `CALL`) — первый байт после поля `length`, инструкция
`RESERVE_LOCALS`.

- Функции идут в порядке, в котором анализатор завершил их разбор; для обычной программы это совпадает
  с порядком ID (`CALL id` → `id`-я функция секции). См. замечание о `SortFunctionsByID` в
  [известных проблемах](06-known-issues.md).
- ID функций верхнего уровня — сквозные с 0. Встроенные функции имеют собственное пространство ID
  (0–6) и вызываются через `SYS_CALL`, поэтому с пользовательскими ID не пересекаются.
- **Соглашение о вызове.** Вызывающий кладёт аргументы на стек слева направо; `CALL id arity` передаёт
  `arity` аргументов, которые становятся локальными слотами `0..arity-1` вызываемой функции. Остальные
  слоты (`arity..n-1`) — локальные переменные. Возвращаемое значение (если тип не `void`) оставляется на
  стеке инструкцией `RET`.
- Для методов слот `0` — это `self`.

## 5. Таблица классов

```
nameLen     i32
name        str(nameLen)
id          i32
parentId    i32            ; -1, если базового класса нет
fieldCount  i32
methodCount i32
methods[methodCount]       ; в формате §4 (с полем length)
```

- Записи отсортированы по `id`.
- В начале таблицы всегда идут встроенные классы: `Object`(0), `ValueObject`(1), `void`(2), `Array`(3),
  `int32`(4), `float32`(5), `bool`(6), `function`(7). У них нет полей; у `Array` может быть один метод —
  сгенерированный базовый конструктор, если программа создаёт массивы.
- Пользовательские классы — ID ≥ 8.
- ID методов локальны для класса (с 0). Методы класса — это его пользовательские методы в порядке
  объявления и, если класс где-либо инстанцируется, сгенерированный базовый конструктор.
- Поля нумеруются с 0 в порядке объявления; `fieldCount` — их количество.

## 6. Набор инструкций

Операнды — `i32`, если не указано иное. Колонка «Стек» — в нотации `[до] → [после]`, вершина стека справа.

### Константы и переменные

| Код | Мнемоника | Операнды | Стек | Описание |
|---|---|---|---|---|
| `1` (`0x01`) | `PUSH_CONSTANT` | `idx` | `[] → [c]` | положить константу из пула |
| `5` (`0x05`) | `LOAD_LOCAL` | `slot` | `[] → [v]` | загрузить локальную переменную |
| `2` (`0x02`) | `STORE_LOCAL` | `slot` | `[v] → []` | сохранить в локальную переменную |
| `6` (`0x06`) | `LOAD_GLOBAL` | `id` | `[] → [v]` | загрузить глобальную переменную |
| `3` (`0x03`) | `STORE_GLOBAL` | `id` | `[v] → []` | сохранить в глобальную переменную |

### Арифметика и сравнение

| Код | Мнемоника | Стек | Описание |
|---|---|---|---|
| `10` (`0x0A`) | `ADD_INT` | `[a b] → [a+b]` | `int32` |
| `11` (`0x0B`) | `SUB_INT` | `[a b] → [a-b]` | `int32` |
| `12` (`0x0C`) | `DIV_INT` | `[a b] → [a/b]` | операнды `int32`, **результат `float32`** (вещественное деление) |
| `13` (`0x0D`) | `MUL_INT` | `[a b] → [a*b]` | `int32` |
| `17` (`0x11`) | `ADD_FLOAT` | `[a b] → [a+b]` | `float32` |
| `18` (`0x12`) | `SUB_FLOAT` | `[a b] → [a-b]` | `float32` |
| `19` (`0x13`) | `MUL_FLOAT` | `[a b] → [a*b]` | `float32` |
| `20` (`0x14`) | `DIV_FLOAT` | `[a b] → [a/b]` | `float32` |
| `29` (`0x1D`) | `INT_EQ` | `[a b] → [a==b]` | результат `bool` |

### Приведение типов

| Код | Мнемоника | Стек |
|---|---|---|
| `14` (`0x0E`) | `CAST_FROM_FLOAT32_TO_INT32` | `[f] → [i]` |
| `16` (`0x10`) | `CAST_FROM_INT32_TO_FLOAT32` | `[i] → [f]` |

### Управление потоком

| Код | Мнемоника | Операнды | Стек | Описание |
|---|---|---|---|---|
| `26` (`0x1A`) | `JMP_IF_FALSE` | `addr` | `[b] → []` | перейти на абсолютное смещение `addr`, если `b == false` |
| `27` (`0x1B`) | `JMP_IF_TRUE` | `addr` | `[b] → []` | зарезервировано, компилятором не генерируется |
| `28` (`0x1C`) | `JMP` | `addr` | `[] → []` | зарезервировано, компилятором не генерируется |
| `15` (`0x0F`) | `HALT` | — | — | остановка; завершает секции глобалов и точки входа |

### Вызовы

| Код | Мнемоника | Операнды | Стек | Описание |
|---|---|---|---|---|
| `9` (`0x09`) | `RESERVE_LOCALS` | `n` | — | первая инструкция каждой функции: выделить `n` локальных слотов |
| `8` (`0x08`) | `CALL` | `funcId`, `arity` | `[a₁…aₙ] → [ret?]` | вызов функции верхнего уровня |
| `4` (`0x04`) | `SYS_CALL` | `nativeId`, `arity` | `[a₁…aₙ] → [ret?]` | вызов встроенной функции (таблица ниже) |
| `30` (`0x1E`) | `CALL_METHOD` | `methodId`, `arity` | `[self a₁…] → [ret?]` | вызов метода; `arity` включает `self`; класс определяется по объекту `self` |
| `7` (`0x07`) | `RET` | — | `[ret?] → …` | возврат; значение (если есть) остаётся на стеке вызывающего |

Встроенные функции (`SYS_CALL`):

| `nativeId` | Функция | `arity` | Результат |
|---|---|---|---|
| 0 | `print(int32)` | 1 | — |
| 1 | `print(float32)` | 1 | — |
| 2 | `print(bool)` | 1 | — |
| 3 | `read()` | 0 | `int32` |
| 4 | `random(int32 min, int32 max)` | 2 | `int32` |
| 5 | `get(Array, int32 index)` | 2 | `int32` |
| 6 | `set(Array, int32 index, int32 value)` | 3 | — |

### Объекты и массивы

| Код | Мнемоника | Операнды | Стек | Описание |
|---|---|---|---|---|
| `25` (`0x19`) | `ALLOCATE_OBJ` | `classId` | `[] → [obj]` | создать объект класса (`fieldCount` полей) |
| `31` (`0x1F`) | `LOAD_FIELD` | `fieldId` | `[obj] → [v]` | прочитать поле |
| `32` (`0x20`) | `STORE_FIELD` | `fieldId` | `[v obj] → []` | записать поле (объект — на вершине, значение под ним) |
| `35` (`0x23`) | `ALLOCATE_ARR` | — | `[len] → [arr]` | создать массив длины `len` |
| `36` (`0x24`) | `ARR_GET` | — | — | зарезервировано (сейчас используется `SYS_CALL 5`) |
| `37` (`0x25`) | `ARR_SET` | — | — | зарезервировано (сейчас используется `SYS_CALL 6`) |

Свободные коды (не используются): `0`, `21`–`24`, `33`, `34`, `≥ 38`.

### Шаблоны генерации

Запись `#v` означает «индекс константы со значением `v`».

```text
; var x = 2 + 3;                 (локальная, слот 0)
PUSH_CONSTANT #2
PUSH_CONSTANT #3
ADD_INT
STORE_LOCAL 0

; var p = Point();               (Point — класс 8, базовый конструктор — метод 2)
ALLOCATE_OBJ 8
CALL_METHOD 2 1                  ; base ctor(self) — инициализирует поля и возвращает self
STORE_LOCAL 0

; p.y = 4;                       (поле y — 1)
PUSH_CONSTANT #4
LOAD_LOCAL 0
STORE_FIELD 1

; print(p.sum());                (метод sum — 0)
LOAD_LOCAL 0
CALL_METHOD 0 1
SYS_CALL 0 1

; базовый конструктор Point (поле x = 0 — поле 0)
<length = 27>
RESERVE_LOCALS 1
PUSH_CONSTANT #0
LOAD_LOCAL 0
STORE_FIELD 0
LOAD_LOCAL 0
RET
RET
```

## 8. Порядок загрузки в VM

1. Проверить `magic` и `version`.
2. Прочитать пул констант.
3. Прочитать `funcCount`; для каждой функции прочитать `length`, запомнить текущую позицию как точку входа
   функции и пропустить `length` байт.
4. Прочитать таблицу классов; методы каждого класса пропускаются так же, по полю `length`.
5. Прочитать `globalCount`, выполнить код инициализации глобалов до `HALT`.
6. Выполнить секцию ENTRY (`CALL Main`).

> Типичная ошибка загрузчика — пропускать `4 + length` байт после **чтения** поля длины: поле уже прочитано,
> и сдвиг получится на 4 байта больше. После `read_i32()` нужно сдвигаться ровно на `length`.

## 9. Версионирование

`HeaderCompiler.BYTECODE_VERSION` необходимо повышать при любом изменении формата файла или набора
инструкций; VM отказывается загружать файл другой версии. История:

| Версия | Изменения |
|---|---|
| `1.39` | добавлены `LOAD_FIELD` / `STORE_FIELD` |
| `1.391` | `CALL_METHOD` берёт объект со стека без снятия (peek); позже, без смены версии, добавлены `ALLOCATE_ARR`, `ARR_GET`, `ARR_SET` |
| `1.392` | перед каждой функцией и методом пишется `length`; завершающий `HALT` после функций убран |
