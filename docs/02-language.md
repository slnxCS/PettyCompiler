# 02 — Справочник языка PettyLang

Этот раздел описывает язык **в том виде, в каком его принимает текущая реализация компилятора**.
Возможности, которые есть в лексере, но не поддерживаются парсером или семантикой, отмечены отдельно.

## 1. Лексическая структура

### 1.1. Кодировка и пробельные символы

Исходник читается как текст (`File.ReadAllText`, UTF-8). Любой символ, для которого `char.IsWhiteSpace`
возвращает `true` (пробел, табуляция, перевод строки и т. д.), разделяет токены и в остальном игнорируется.

### 1.2. Комментарии

| Вид | Синтаксис | Пример |
|---|---|---|
| Однострочный | `#` до конца строки | `var x = 1; # комментарий` |
| Многострочный | `#<` … `>#` | `#< несколько\nстрок >#` |

Незакрытый многострочный комментарий — синтаксическая ошибка `Multi-line comment termination required (>#)`.
Вложенность многострочных комментариев не поддерживается.

### 1.3. Идентификаторы

```
identifier = (letter | "_") { letter | digit | "_" }
```

`letter`/`digit` — в смысле `char.IsLetter`/`char.IsLetterOrDigit`, т. е. допускаются буквы Unicode
(в том числе кириллица). Регистр значим.

### 1.4. Ключевые слова

| Слово | Назначение | Поддержка |
|---|---|---|
| `var` | объявление переменной/поля | ✅ |
| `func` | объявление функции/метода | ✅ |
| `class` | объявление класса | ✅ |
| `return` | возврат из функции | ✅ |
| `if` | условие | ✅ |
| `as` | приведение типа | ✅ |
| `true`, `false` | логические литералы | ✅ |
| `else` | — | ⛔ только зарезервировано (парсер выдаёт `Unexpected 'Else'`) |
| `import`, `package` | — | ⛔ только зарезервировано |

Ключевое слово нельзя использовать как идентификатор.

### 1.5. Литералы

| Вид | Пример | Токен | Тип в языке |
|---|---|---|---|
| Целое | `42`, `-7` | `IntNumber` | `int32` |
| Вещественное | `3.14`, `-0.5` | `FloatNumber` | `float32` |
| Логическое | `true`, `false` | `True`/`False` | `bool` |
| Строка | `"text"` | `String` | ⛔ ошибка семантики (тип `String` не подключён) |
| Символ | `'a'` | `Char` | ⛔ не работает (см. [известные проблемы](06-known-issues.md)) |

Особенности чисел:

- **Знак минус — часть литерала**, если `-` стоит непосредственно перед цифрой. Поэтому `x-1` разбирается
  как `x`, `-1` и даёт синтаксическую ошибку. Пишите бинарный минус с пробелом: `x - 1`.
- Вещественное число распознаётся, если после цифр идёт `.` и за ней цифра. Экспоненциальная запись
  (`1e5`) и суффиксы не поддерживаются.
- Целые литералы должны помещаться в `int32`.
- Строки — без escape-последовательностей; могут содержать переводы строк. Незакрытая строка —
  ошибка `String termination required`.

### 1.6. Операторы и разделители

| Лексема | Токен | Используется парсером |
|---|---|---|
| `+` `-` `*` `/` | `Plus`, `Minus`, `Asteric`, `Slash` | ✅ арифметика |
| `==` | `Equals` | ✅ сравнение |
| `=` | `Equate` | ✅ присваивание |
| `+=` `-=` `*=` `/=` | `PlusEquate` … | ⚠️ разбираются, но семантика выдаёт `NotImplementedException` |
| `(` `)` | `LParen`, `RParen` | ✅ |
| `{` `}` | `LCurlyBrace`, `RCurlyBrace` | ✅ |
| `:` `;` `.` `,` | `Colon`, `Semicolon`, `Dot`, `Comma` | ✅ |
| `[` `]` `<` `>` | `LSquareBracket` … `RAngleBrace` | ⛔ только лексер |

Лексер выбирает самое длинное совпадение (до 2 символов), поэтому `==` — один токен, а не два `=`.
Любой другой символ — ошибка `Unknown symbol : <c>`.

## 2. Грамматика

Формальная грамматика в EBNF, точно соответствующая `Parser.cs`:

```ebnf
program        = { statement } EOF ;

statement      = varDecl
               | funcDef
               | classDef
               | returnStmt
               | ifStmt
               | block
               | identStmt ;

block          = "{" { statement } "}" ;

varDecl        = "var" IDENT ( ":" path [ "=" expression ] | "=" expression ) ";" ;

funcDef        = "func" IDENT "(" [ param { "," param } ] ")" [ ":" [ path ] ] block ;
param          = IDENT ":" path ;

classDef       = "class" IDENT ":" [ path ] block ;

returnStmt     = "return" [ expression ] ";" ;

ifStmt         = "if" expression ":" block ;

identStmt      = path ( assignOp expression ";" | ";" ) ;
assignOp       = "=" | "+=" | "-=" | "*=" | "/=" ;

(* выражения: от низшего приоритета к высшему *)
expression     = equality ;
equality       = additive { "==" additive } ;
additive       = multiplicative { ( "+" | "-" ) multiplicative } ;
multiplicative = cast { ( "*" | "/" ) cast } ;
cast           = primary { "as" path } ;
primary        = INT | FLOAT | "true" | "false" | STRING
               | path
               | "(" expression ")" ;

path           = pathPart { "." pathPart } ;
pathPart       = IDENT { "(" [ expression { "," expression } ] ")" } ;
```

### 2.1. Приоритет операторов

| Приоритет | Операторы | Ассоциативность |
|---|---|---|
| 1 (высший) | `(…)`, вызов `f(…)`, доступ `.` | слева направо |
| 2 | `as` | слева направо |
| 3 | `*` `/` | слева направо |
| 4 | `+` `-` | слева направо |
| 5 (низший) | `==` | слева направо |

Унарных операторов нет (кроме знака в числовом литерале). Присваивание — инструкция, а не выражение.

### 2.2. Синтаксические замечания

- Двоеточие после списка параметров функции **необязательно**: `func f() { }` и `func f() : { }` эквивалентны
  (возвращают `void`). Тип возврата пишется после двоеточия: `func f() : int32 { … }`.
- Двоеточие после имени класса **обязательно**: `class A : { }`; базовый класс — `class B : A { }`.
- После условия `if` обязательно двоеточие: `if x == 1 : { … }`.
- Инструкция-выражение должна начинаться с идентификатора: `f(1);`, `obj.method();`. Выражения вида
  `(a + b);` или `1;` как инструкции недопустимы.
- `path` начинается только с идентификатора: `(expr).field` не поддерживается.
- Цепочка вызовов `f()()` синтаксически разбирается, но семантика использует только первый список аргументов.

## 3. Типы

### 3.1. Встроенные типы

Все встроенные типы регистрируются в `BuiltIn.Init()` в глобальной области видимости.

| Имя | ID класса | Базовый класс | Описание |
|---|---|---|---|
| `Object` | 0 | — | корень иерархии |
| `ValueObject` | 1 | `Object` | база для значимых типов |
| `void` | 2 | `Object` | «нет значения»; тип функций без возвращаемого значения |
| `Array` | 3 | `Object` | массив целых чисел (в разработке) |
| `int32` | 4 | `ValueObject` | 32-битное знаковое целое |
| `float32` | 5 | `ValueObject` | 32-битное число с плавающей точкой IEEE 754 |
| `bool` | 6 | `ValueObject` | логическое значение |
| `function` | 7 | `Object` | тип значения-функции |

Пользовательские классы получают ID начиная с 8 в порядке объявления.

### 3.2. Правила совместимости типов

Система типов **строгая и номинальная**: типы сравниваются на точное равенство (`ClassSymbol` по ссылке).

- Неявных преобразований нет: `var f : float32 = 1;` — ошибка `Cannot convert from 'int32' to 'float32'`.
- Наследование не даёт совместимости: экземпляр подкласса нельзя присвоить переменной базового класса.
- Явные преобразования — через `as`:

| Из \ В | `int32` | `float32` | тот же тип |
|---|---|---|---|
| `int32` | — | ✅ `CAST_FROM_INT32_TO_FLOAT32` | ✅ без кода |
| `float32` | ✅ `CAST_FROM_FLOAT32_TO_INT32` | — | ✅ без кода |
| прочие | ⛔ | ⛔ | ✅ без кода |

### 3.3. Операторы над встроенными типами

| Левый | Правый | `+` `-` `*` | `/` | `==` |
|---|---|---|---|---|
| `int32` | `int32` | `int32` | `float32` ⚠️ | `bool` |
| `float32` | `float32` | `float32` | `float32` | ⛔ |
| `bool` | `bool` | ⛔ | ⛔ | ⛔ |

⚠️ `int32 / int32` имеет **статический тип `float32`**, но кодируется инструкцией `DIV_INT`
(см. [известные проблемы](06-known-issues.md)). Операнды разных типов (`int32 + float32`) недопустимы —
сначала приведите один из них через `as`.

## 4. Переменные

```petty
var a = 10;              # тип выводится из инициализатора: int32
var b : float32 = 1.5;   # явный тип — должен совпадать с типом инициализатора
var c : int32;           # объявление без инициализатора (см. ограничения ниже)
```

- Переменная обязана иметь тип или инициализатор (`var x;` — ошибка).
- Переменная типа `void` запрещена.
- **Глобальные переменные** объявляются на верхнем уровне файла; их инициализаторы выполняются до вызова
  `Main` (секция глобалов в байткоде).
- **Локальные переменные** живут внутри функции. Блоки `{ }` и тело `if` создают вложенную область:
  имя из внешней области можно перекрыть (shadowing), повторное объявление в той же области — ошибка
  `Variable '<name>' is already exist`.
- Объявление без инициализатора (`var c : int32;`) сейчас корректно работает **только для полей классов**;
  для локальных и глобальных переменных генератор кода падает (см. [известные проблемы](06-known-issues.md)).

### Присваивание

```petty
a = a + 1;
obj.field = 5;
```

Цель присваивания должна быть переменной или полем; тип значения обязан точно совпадать с типом цели.
Составные операторы `+=`, `-=`, `*=`, `/=` разбираются, но пока не реализованы.

## 5. Функции

```petty
func add(a : int32, b : int32) : int32 {
    return a + b;
}

func log(x : int32) : {      # возвращает void
    print(x);
}
```

- Параметры передаются по значению (для объектов — по ссылке на объект) и являются локальными переменными.
- **Перегрузка**: функции с одним именем различаются списком типов параметров. Тип возврата в сигнатуру
  не входит. Выбор перегрузки — по точному совпадению типов аргументов. Дублирующая перегрузка —
  ошибка `Overload of function '<name>' with same parameters(...) is already exist`.
- **Рекурсия** поддерживается.
- **Порядок объявления важен**: функция должна быть объявлена выше места вызова (анализ однопроходный).
  Исключение — методы внутри класса: они видны друг другу независимо от порядка.
- **Проверка `return`**: функция с не-`void` типом должна содержать хотя бы один `return` (проверяется
  наличие, а не то, что все ветви возвращают значение). `return;` без значения допустим только в `void`-функциях.
- Вызов функции как инструкции допустим для любой функции; возвращаемое значение при этом не удаляется со
  стека (инструкции `POP` нет).
- Инструкции (выражения, присваивания, `if`, `return`) допустимы только внутри функций; на верхнем уровне —
  только `var`, `func` и `class`. Иначе ошибка `Cannot do this operation outside a function`.

### Точка входа `Main`

Каждая программа обязана объявить ровно одну функцию верхнего уровня:

```petty
func Main() : { … }
```

Требования (проверяются в `Analyzer`): не метод, без параметров, тип возврата `void`, единственная.
Нарушения дают ошибки `Main entry point should be function, not method`,
`Main function should not take any parameters`, `Main function must return void`,
`Main entry point is already exist in this program`, `Program should have Main Function`.

## 6. Условный оператор

```petty
if x == 10 : {
    print(x);
}
```

Условие должно иметь тип `bool`. Ветки `else` нет. Тело — отдельная локальная область видимости.

## 7. Классы

```petty
class Point : {
    var x = 0;          # поле с инициализатором
    var y : int32;      # поле без инициализатора (значение не определено)

    func sum() : int32 {
        return self.x + self.y;
    }

    func move(dx : int32) : {
        self.x = self.x + dx;
    }
}

func Main() : {
    var p = Point();    # создание экземпляра
    p.y = 4;
    p.move(3);
    print(p.sum());     # 7
}
```

### 7.1. Поля

- Поля объявляются через `var` непосредственно в теле класса.
- Инициализаторы полей выполняются при создании объекта в сгенерированном **базовом конструкторе**.
- Поля без инициализатора остаются неинициализированными (значение определяется VM).
- Номера полей (`ID`) присваиваются в порядке объявления, начиная с 0.

### 7.2. Методы и `self`

- Методы объявляются через `func` внутри класса.
- Каждый метод получает **неявный первый параметр `self`** — ссылку на текущий объект.
- Внутри метода доступ к полям и другим методам — **только через `self`**: `self.x`, `self.sum()`.
  Обращение по голому имени (`x`) — ошибка `Name 'x' does not exist in current context`.
- Метод с именем `Main` запрещён.

### 7.3. Создание объектов и конструкторы

Выражение `ИмяКласса()` создаёт объект: выделяет память (`ALLOCATE_OBJ`) и вызывает базовый конструктор,
который выполняет инициализаторы полей и возвращает `self`.

Пользовательские конструкторы пока не поддерживаются: метод с именем класса конфликтует со
сгенерированным конструктором (`Function '<Class>' is already exist`), а конструктор принимает только
пустой список аргументов.

### 7.4. Наследование

Синтаксис `class B : A { }` разбирается, и ID базового класса записывается в байткод, но поля и методы
базового класса **не наследуются** при семантическом анализе (обращение `b.a` к полю из `A` — ошибка).
Пользовательские классы без явной базы не наследуются от `Object` (в байткоде `parent = -1`).

### 7.5. Что допустимо в теле класса

Анализатор обрабатывает в теле класса только объявления `var` (поля) и `func` (методы). Все остальные
инструкции — в том числе вложенные `class` — **молча игнорируются**: вложенный класс не регистрируется,
и обращение `Outer.Inner` даёт ошибку `'Outer' does not contains field with name 'Inner'`.

## 8. Массивы (в разработке)

```petty
func Main() : {
    var a = Array(10);   # массив int32 длиной 10
    set(a, 0, 42);
    print(get(a, 0));
}
```

`Array(n)` компилируется в `PUSH n; ALLOCATE_ARR`. Чтение и запись — через встроенные функции `get`/`set`.
Индексатор `a[i]` не поддерживается. Класс `Array` отсутствует в таблице классов байткода
(см. [известные проблемы](06-known-issues.md)).

## 9. Встроенные функции

Объявлены в `Builtin.cs`; вызываются инструкцией `SYS_CALL <id> <arity>`.

| ID | Сигнатура | Описание |
|---|---|---|
| 0 | `print(number : int32) : void` | вывести целое |
| 1 | `print(number : float32) : void` | вывести вещественное |
| 2 | `print(value : bool) : void` | вывести логическое |
| 3 | `read() : int32` | прочитать целое со стандартного ввода |
| 4 | `random(min : int32, max : int32) : int32` | случайное целое в диапазоне |
| 5 | `get(array : Array, index : int32) : int32` | элемент массива |
| 6 | `set(array : Array, index : int32, num : int32) : void` | записать элемент массива |

Встроенные функции можно перегружать пользовательскими: например, `func print(ar : Array, len : int32)`
добавляет новую перегрузку к `print`.

## 10. Разрешение имён

Имя ищется от текущей области видимости к глобальной (`Local → Function → … → Global`).

- **Без вызова** (`name`): сначала переменная, затем класс, затем функция (значение типа `function`).
- **С вызовом** (`name(...)`): сначала функция (выбор перегрузки), затем переменная, затем класс
  (создание экземпляра). Функции не являются значениями первого класса: `var g = f;` — ошибка
  `Value required`, поэтому ветка «вызов переменной» на практике недостижима.
- **После точки** (`a.b`): поиск идёт только в членах `a` (без подъёма к родительским областям).

## 11. Полный пример

```petty
# Ввод и вывод массива рекурсией
func array_write(ar : Array, index : int32, stopIndex : int32) : {
    set(ar, index, read());
    index = index + 1;
    if index == stopIndex : {
        return;
    }
    array_write(ar, index, stopIndex);
}

func print_element(ar : Array, index : int32, stopIndex : int32) : {
    print(get(ar, index));
    index = index + 1;
    if index == stopIndex : {
        return;
    }
    print_element(ar, index, stopIndex);
}

func print(ar : Array, len : int32) : {
    print_element(ar, 0, len - 1);
}

func Main() : {
    var len = 10;
    var ar = Array(len);
    array_write(ar, 0, len - 1);
    print(ar, len);
}
```
