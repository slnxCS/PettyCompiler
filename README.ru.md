В этом репозитории — **компилятор PettyLang**, написанный на C#. Он переводит исходники на PettyLang в
байткод для **[PettyVM](https://github.com/slnxCS/PettyVM)** — стековой виртуальной машины на C.

```petty
class Counter : {
    var value = 0;

    func next() : int32 {
        self.value = self.value + 1;
        return self.value;
    }
}

func fact(n : int32) : int32 {
    if n == 0 : return 1;
    return n * fact(n - 1);
}

func Main() {
    var c = Counter();
    print(c.next());   # 1
    print(c.next());   # 2
    print(fact(5));    # 120
    print(7 / 2);      # 3.5
}
```

## Возможности

- **Статическая типизация** с выводом типов переменных: `var x = 1;` или `var x : int32 = 1;`
- **Встроенные типы** `int32`, `float32`, `bool` и явные преобразования через `as`
- **Классы** с полями, инициализаторами полей и методами (`self` передаётся неявно)
- **Функции** с перегрузкой по типам параметров и рекурсией
- **Массивы** `int32` через `Array(n)`, `get` и `set`
- **`if`** с телом-блоком или одной инструкцией
- **Встроенные функции**: `print`, `read`, `random`, `get`, `set`
- **Компактный бинарный формат**: пул констант, таблица функций, таблица классов и точка входа в одном файле
- Ошибки компиляции с номером строки и столбца

> PettyLang — хобби-проект на ранней стадии. Циклы, `else`, строки, операторы сравнения кроме `==` и
> наследование членов классов пока не реализованы — см. [Известные проблемы](docs/06-known-issues.md).

## Быстрый старт

### Требования

- [.NET SDK 10.0](https://dotnet.microsoft.com/download) или новее — для сборки компилятора
- `gcc` и `make` — для сборки [PettyVM](https://github.com/slnxCS/PettyVM) и запуска программ

### Сборка

```bash
git clone https://github.com/slnxCS/PettyCompiler.git
cd PettyCompiler
dotnet build PettyLang/PettyLang.csproj -c Release
```

### Компиляция и запуск программы

```bash
# компиляция
dotnet PettyLang/bin/Release/net10.0/PettyLang.dll -i hello.pt -o compiled.pt

# запуск на PettyVM
git clone https://github.com/slnxCS/PettyVM.git ../PettyVM
make -C ../PettyVM
cp compiled.pt ../PettyVM/ && cd ../PettyVM && ./build/main compiled.pt
```

Версия байткода в файле должна совпадать с версией, которую ожидает PettyVM (сейчас **1.392**).

## Использование

```
PettyLang -i <исходник> -o <выходной файл> [опции]
```

| Опция | Описание |
|---|---|
| `-i`, `--input <путь>` | исходный файл |
| `-o`, `--output <путь>` | куда записать байткод |
| `-d`, `--debug` | не перехватывать исключения компилятора (для отладки самого компилятора) |
| `-v`, `--version` | вывести версии компилятора и байткода |
| `-h`, `--help` | справка |

Без `-i` или `-o` выводится справка.

## Как это работает

```
исходник ─▶ Lexer ─▶ Parser ─▶ AST ─▶ Analyzer ─▶ Compiler ─▶ байткод PTVM
  *.pt      токены           дерево   символы,      байты
                                      типы, ID,
                                      пул констант
```

1. **Лексер** превращает текст в токены.
2. **Парсер** — рекурсивный нисходящий, написан вручную — строит AST.
3. **Анализатор** разрешает имена, проверяет типы, выбирает перегрузки и назначает ID переменным, функциям и классам.
4. **Компилятор** генерирует байткод: заголовок, пул констант, функции, таблицу классов, глобальные
   переменные и вызов `Main`.

Весь конвейер доступен одним вызовом: `Program.Start(string source) : byte[]`.

## Структура проекта

```
PettyLang/            компилятор (консольное приложение)
  Lexer/              токены и лексер
  AST/                синтаксическое дерево и парсер
  Semantic/           области видимости, символы, семантический анализатор
  Compiler/           генерация кода, пул констант, заголовок файла
  Builtin.cs          встроенные типы и функции
Tests/                тесты на NUnit
docs/                 техническая документация
```

## Тесты

```bash
dotnet test PettyLang.slnx                                     # все тесты
dotnet test PettyLang.slnx --filter "TestCategory!=KnownBug"   # без известных ошибок
```

Тесты покрывают лексер, парсер, семантический анализ и точные листинги байткода. Тесты категории
`KnownBug` описывают ожидаемое поведение для ещё не исправленных ошибок и падают, пока ошибка не исправлена.
